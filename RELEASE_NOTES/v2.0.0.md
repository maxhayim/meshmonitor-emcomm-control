## EmComm Control v2.0.0 — LIVE + EXERCISE

This major release evolves the original SET-only project into **EmComm Control**, a dual-mode MeshMonitor tool for both real-world emergency communications and simulated exercises.

### Renamed
- Project: SET Exercise Control → **EmComm Control**
- Runtime: `mm_arrl_set.py` → `mm_emcomm_control.py`
- Runtime data directory: `mm_arrl_set_data/` → `mm_emcomm_control_data/`

### Added
- **LIVE mode** for operator-entered real-world check-ins, SITREPs, message traffic, operational status, and announcements.
- **EXERCISE mode** for drills, ARRL® SET use, simulated traffic, and timed exercise injects.
- New `EMCOMM` command prefix.
- Local mode administration:
  - `--mode live --confirm-live`
  - `--mode exercise`
  - `--mode status`
- Operator-supplied `--announce` action.
- Mode-aware traffic IDs: `EC-###` in LIVE and `EX-###` in EXERCISE.
- Best-effort migration of legacy SET state/log data.
- Expanded security, contribution, issue-template, and GitHub Pages documentation.

### Safety / operational behavior
- LIVE mode can only be enabled locally; inbound mesh traffic cannot activate it.
- Simulated injects are blocked while LIVE.
- The legacy `SET` prefix is rejected while LIVE.
- LIVE mode does not fabricate or infer incident conditions.
- Traffic acknowledgments do not claim guaranteed delivery to the named recipient.

### Compatibility
- Legacy `SET CHECKIN`, `SET SITREP`, `SET TRAFFIC`, `SET STATUS`, and `SET HELP` remain supported in EXERCISE mode.
- MeshMonitor operation remains compatible with Meshtastic, MeshCore, and other mesh networks supported by MeshMonitor.
- Python standard-library only; no pip dependencies.

### Primary commands
```text
EMCOMM CHECKIN <CALLSIGN> <LOCATION> <POWER> <ROLE>
EMCOMM SITREP <LOCATION> <STATUS>
EMCOMM TRAFFIC <TO> <TEXT>
EMCOMM STATUS
EMCOMM HELP
```
